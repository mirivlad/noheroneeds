# Полный локальный и выпускной прогон

Последовательный набор вырос до 644 тестов в 98 группах; прежний суммарный
CPU-прогон превышал 2400 секунд. Чтобы полный выпускной набор укладывался
в ограниченное время без пропуска проверок, добавлен параллельный запуск
групп. По умолчанию направленные команды сохраняют один процесс.

```sh
python3 -m unittest discover -s tools/tests -v
TEST_JOBS=6 TEST_TIMEOUT=2400 tools/run_tests.sh
```

В выпускном GitHub workflow используются четыре работника и прежний
2400-секундный предел. События обычных push/PR по-прежнему не запускают CI.
Обновление импортов и проверка компиляции выполняются до разделения групп.
Каждая группа использует штатный `tests/framework/run.gd` и собственный
XDG-профиль; её дочерние серверы наследуют этот профиль.

`tools/run_tests_parallel.py` сохраняет полный инвентарь выбранных методов,
хеши игровых источников/контента/тестов и раннера, отдельные журналы и итог
в `build/test-runs/`. Проверяются код завершения, единственная итоговая
строка, точное число выполненных и успешных сценариев, ноль неуспешных
проверок, точное число разрешённых ошибок движка и отсутствие ранней
остановки. Пустой выбор не может дать успешный итог. При переполнении
журнала или остановке завершается вся группа дочерних процессов.
Изменение исходников во время прогона делает общий итог неуспешным.
Временные базы и ключи после нормального завершения удаляются, компактные
журналы и сводка остаются.

Проверка самого раннера: три Python-сценария отказов/инвентаря прошли;
настоящие шесть CBOR-тестов и девять тестов трёх групп core прошли.
Подставленный неуспешный процесс был отвергнут с кодом 1, а не принят за
пустой успешный прогон. Полный выпускной прогон с новым раннером фиксируется
отдельно после подготовки версии.
