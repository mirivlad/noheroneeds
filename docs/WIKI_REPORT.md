# NHN Wiki 2.0 — результат интеграции

Рабочая ветка `codex/wiki-2.0` основана на актуальном игровом `main` (v0.17.0).
Сайт из `feat/game-site-wiki` перенесён с сохранением истории, без замены игрового
кода старой копией. Из игровых настроек изменено только исключение `site/`
из экспорта; оно сопровождается обоснованной внутренней записью проверки.

## Сайт и данные

- История содержит 19 подтверждённых GitHub Releases от первого до v0.17.0.
  Теги без публикации не добавляются. Патчноуты v0.17.0 — «Таверны и постоялые
  дворы», с настоящими кадрами игры и ограничением генерации в старых мирах.
- Справочник создаётся из всех пакетов контента: 286 игровых записей,
  все 72 предмета, 41 рецепт и 6 профессий; 14 редакционных руководств.
  Служебные определения внешности/звука и шаблоны летописей не выдаются за предметы.
- Есть источники добычи, рецепты/количества, станции, умения, обучение/условия,
  базовые торговые предложения и обратные связи. Для каждого поля/ребра доступен
  исходный файл и JSON Pointer либо символ небольшого адаптера `Hospitality`.
- Железо: руда → плавка (2 руды + бревно) → слиток → меч
  (3 слитка + доска + бечёвка) → кузнец (55 монет, доверие 1,
  оружейное дело 10). Аналогичные цепочки руды/плавки/учителя проверены для
  меди, серебра и золота; параметры берутся из JSON.
- Раздел таверн объясняет поиск, разговор, питание, конкретную кровать/комнату,
  лестницы и сон, сроки аренды, новости, три поручения, обучение и остановки
  караванов. Цены, награды и условия подставляются из игровых данных.

## Обязательный процесс

Корневой `AGENTS.md`, `site/AGENTS.md`, ссылка в инструкции Claude, шаблон PR
и [WIKI_WORKFLOW.md](WIKI_WORKFLOW.md) задают обязательную документацию.
Карта механик связывает исходники и руководства. Проверки учитывают содержимое
и хеши, реальные правки руководств, корректность каталога и changelog.
`no-player-facing-change` требует конкретного обоснования, точной области и
дополнительного контракта/тестов для крупных внутренних изменений.

`release.yml` не запускает упаковку без игровых и документационных/браузерных
проверок. Обычный тег и ручной запуск проходят одинаковый барьер; существующий
опубликованный выпуск нельзя случайно переупаковать. Публикуется подготовленный
игровой changelog, а не автоматически собранный список технических коммитов.

Публичная вики собирается по последнему опубликованному тегу. Для старого v0.17.0
закрепляется отдельный неизменяемый снимок документации; последующие теги содержат
сайт полностью. Тест с отдельной Git-историей проверяет, что будущий `main` не
просачивается ни в каталог, ни в руководства старой публичной версии.

## Проверка и предпросмотр

Локально: полный игровой набор — **521 тест, 0 провалов**; **31 тест Python**
и **8 сценариев Playwright** прошли. Тесты каталога,
документационных отказов и публикации, а также Playwright выполняются командой
`tools/site/test.sh`. Сценарии включают новые пакеты/ID, потерянные ссылки,
дубликаты, обучение, детерминизм, отсутствие changelog, устаревшие подтверждения,
обоснованные/недопустимые внутренние исключения и изоляцию опубликованной версии.

Браузер проверяет главную, переходы, поиск, цепочку железа, услуги таверны,
отсутствующий ID, мобильное меню и границы карточки, контраст, патчноуты и выбор
последнего релиза после прокрутки вниз, включая регрессию 0.13/0.12.

Предпросмотр рабочей версии: `python3 tools/site/build.py`, затем
`python3 tools/site/serve.py` → `http://127.0.0.1:18764/noheroneeds/`.
Workflow Website checks прикладывает исходный статический предпросмотр,
отдельную сборку опубликованного снимка и отчёт/кадры Playwright.
Примеры кадров находятся в `site/test-results/` после локального прогона.

## Что остаётся владельцу

Новый сайт этой задачей не развёртывается до разрешённого слияния PR.
Действующая конфигурация проверена через API: Pages использует старую ветку,
а окружение `github-pages` допускает только `feat/game-site-wiki`.
Нужны переключение Source на GitHub Actions и разрешения окружения для
`main` и тегов `v*.*.*`; точные шаги — в [инструкции](WIKI_WORKFLOW.md#настройка-владельцем-репозитория).
После слияния проверить успешный Published wiki и
`https://mirivlad.github.io/noheroneeds/data/publication.json`.

Новый игровой релиз не создаётся; опубликованные Releases и main не изменяются.
