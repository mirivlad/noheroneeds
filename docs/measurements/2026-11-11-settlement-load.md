# Нагрузка после развития поселений — 11.11.2026

Godot 4.7.2, Linux, Xeon E5-2680 v4, headless/Dummy. Штатный выделенный
сервер и 20 ботов через настоящий ENet, плюс 500 существ в окрестности
старта. Измеряемое игровое окно — 60 секунд. Это намеренно плотная
искусственная толпа; она не является обычной плотностью мира.

```sh
TEST_TIMEOUT=600 tools/run_tests.sh --bench --only=bench_load --test=bench_20_players_500_creatures --load_seconds=60
```

Все 20 клиентов играли, 289 запросов получили ответы, неотвеченных в конце
нет. Задержка подтверждения p50 — 108 мс, p99 — 1115 мс, максимум — 1152 мс.
Средняя частота в учтённых окнах — 19,2 тика/с, трафик — 14,1 КБ/с на клиента.
На поздних окнах медиана тика — 35–40 мс; p99 отдельных поздних окон —
54–65 мс. Наибольший тик — 923,639 мс в раннем окне, 866 мс из него —
секция существ. Значительные текущие расходы остаются у AI и снимков.

Таким образом, **жёсткие 20 Гц под этой нагрузкой не подтверждены**.
Проверка прошла по своим игровым условиям (все клиенты играют, запросы
отвечены), а не по отсутствующему в ней порогу задержки. Этот замер не
используется как доказательство ускорения общего сервера: сопоставимое
«до/после» сделано отдельно для расчёта сметы, не для всей симуляции.
Снижения числа существ, частоты AI, радиуса видимости или объёма игровых
правил ради результата не выполнялось.

Первоначальная попытка стенда прекращалась до игры: общий десятисекундный
тайм-аут ожидания LISTENING был короче холодной подготовки мира с толпой.
Отдельный запуск подтвердил готовность через 17,535 с. Стенд теперь
разрешает до 180 с на готовность; это время не включается в окно игры.
